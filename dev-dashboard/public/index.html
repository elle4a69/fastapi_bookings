App Stack Communication Lifecycle

This flow chart shows the live data lifecycle. The Mapbox Client UI communicates with the FastAPI Bookings REST API. Booking transactions fire webhooks to the Chatwoot Support Portal, which redirects them to the Bookings AI Agent microservice for synthetic responder processing. SigNoz APM collects tracing data across all nodes in the background.

📖 Workspace Architecture Briefing

Welcome back! This stack forms a complete distributed reservation ecosystem. When you return to this code after several months, use this reference guide to quickly orient yourself.

📂 Key Directories & Roles

  • F:\Projects\fastapi_bookings: Core backend system. Written in Python/FastAPI with SQLite, using Alembic for migrations. Exposes standard reservation endpoints.
  • F:\Projects\fastapi_bookings\mapbox: Front-end client interface. Written in React, TypeScript, and Vite. Displays location pins on Mapbox maps.
  • F:\Projects\bookings_ai_agent: Autocomplete responder microservice. Runs on port 5500. Handles synthetic simulated bookings and automations.
  • E:\Projects\chatwoot-source: Open-source customer engagement platform. Used to receive conversation streams and hand off to human support when the AI agent triggers an override.
  • F:\Projects\signoz: Telemetry collector. Runs SigNoz APM to capture performance logs and endpoint speeds via OpenTelemetry hooks.

🛠️ Setup & Operations Reminder

  • Backend virtual environments are set up locally under .venv/ inside each respective python folder.
  • Startup scripts (start.bat) inside the folders handle virtual environment activation automatically.

🚀 Quick Commands Reference

FastAPI Backend: python -m uvicorn app.main:app --port 8000
AI Agent Microservice: python -m app.main
Vite Frontend: npm run dev
